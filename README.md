# Satellite Map / Minecraft 卫星地图

[![Tag build and release](https://github.com/ShadowYinb/satellite-map/actions/workflows/release.yml/badge.svg)](https://github.com/ShadowYinb/satellite-map/actions/workflows/release.yml)

客户端 Fabric MOD，目标版本 **Minecraft Java 1.21.11 / Fabric Loader 0.18.4 / Java 21**。
从公开的 Dynmap 网站读取配置、玩家位置和地图瓦片，在游戏 HUD 显示小地图，并提供可拖动、缩放的大地图。

## 安装

1. 使用 Minecraft **1.21.11**，安装 **Fabric Loader 0.18.4**。
2. 将 `satellite-map-1.5.4.jar` 和适用于 **1.21.11** 的 **Fabric API 0.141.3 或更新兼容版本**放入该游戏实例的 `mods` 文件夹。升级时移除旧版 Satellite Map JAR，保留原配置即可。
3. 启动游戏，连接服务器。服务器端无需安装本 MOD。
4. 可选安装 **Mod Menu 17.x**，可从模组列表进入设置；没有 Mod Menu 时可直接按 `O`。

从 [GitHub Releases](https://github.com/ShadowYinb/satellite-map/releases) 下载 MOD JAR，另行安装对应的 Fabric API。Release 中的安装 ZIP 包含本 MOD 和说明文档，不包含 Fabric API。如果已有 Fabric API，请仅保留一份适用于 1.21.11 的版本。
本地交付目录 `dist` 中的历史安装包可能附带 Fabric API；该目录不提交到 Git 仓库。

## 操作

| 默认按键 | 功能 |
| --- | --- |
| `M` | 打开 / 关闭大地图 |
| `O` | 打开设置 |
| `N` | 显示 / 隐藏小地图 |
| `B` | 在当前服务器匹配的映射组之间手动切换 |
| `=` | 放大小地图 |
| `-` | 缩小小地图 |
| 按住 `Tab` | 小地图显示玩家 / 标记名称、生物头像；松开恢复简洁显示 |
| 大地图内左键拖动 | 浏览地图，退出跟随模式 |
| 大地图内滚轮 / 加减按钮 | 缩放 |
| 大地图内空格 / 定位按钮 | 恢复跟随玩家 |

所有快捷键都可在游戏的“选项 → 控制 → 按键绑定 → 卫星地图”修改。
小地图采用细描边浮窗，X/Y/Z 坐标直接浮在游戏画面上，不再使用不透明的底部信息块；映射名称在按住 Tab 时显示。
按 `O` → “小地图显示”，可用滑块分别设置宽度、高度（96–320 GUI 像素）和缩放；点击“拖动调整位置…”可在画面中直接拖动，再返回设置页“保存并应用”。
四角锚点、显示开关和瓦片刷新间隔也可调整。屏幕缩小时自动限制小地图位置和尺寸，使其留在可见区域。
“原版按键绑定…”按钮直接打开游戏原生按键界面，六个按键均列在“卫星地图”分类下，可改成其他键盘键或鼠标键，绑定由原版游戏保存。Tab 功能跟随原版“显示玩家列表”的键绑定。
大地图铺满整个窗口，按钮和信息浮在地图上方，整个背景均可拖动浏览。
本 MOD 不暂停游戏。

## 小地图的本地实时地形

1.5.0 起，小地图优先显示玩家附近已加载的游戏区块，不再用网页旧图覆盖这一带。方块变化后自动更新；周围约 100 格内的区块分批处理，距离最近的区块先显示。未收到的区块和更远的区域继续使用网页卫星图。
本地层只读取客户端已经接收到的区块，不向服务器额外加载区块。区块卸载、离开世界或切换维度时会移除对应图像，避免把其他世界的地形带过来。大地图继续使用网页卫星图。
1.5.1 改用当前资源包的方块顶部材质平均色，再乘以群系染色，草、树叶和水不再直接使用过亮的染色值。移除了区块内部额外添加的明暗条纹，并从同位置的网页原始细瓦片学习各类材质的配色；跳过颜色明显不同、空白或过暗的样本，避免把新建筑重新染成网站上的旧地形。校准只读取已经加载的瓦片，不额外发起下载。
校准稳定后固定配色，网站 / 世界 / 图层或资源包改变时重新建立，避免移动时整片地图不断变色。网页使用专用资源包、特殊光照、季节色或过期地形时，不能保证所有像素完全相同；本地仍以实际收到的方块为准。
主世界和末地显示地表；有天花板的维度（例如下界）从玩家高度附近向下寻找地形，避免把整个下界显示成顶部基岩。斜视图层会按网站的投影方向铺设顶视地形，自动配色校准用于顶视图层。

1.5.1 的小地图、跟随模式的大地图和附近实体使用按帧插值的位置。网页原始瓦片、持久合成图和实时地形共用连续坐标，不再分别取整后绘制；自身头像固定在小地图中央，朝向线也随帧更新。
1.5.2 进一步让标记点、玩家和生物头像连同边框整体在小数坐标上移动，避免图标仍按整 GUI 像素跳动。自身朝向线采用连续旋转的细矩形绘制。
1.5.3 将公会、Residence、战区等区域的填色和边线也改为保留小数坐标的连续几何绘制，替代逐像素扫描和取整。文字及其背景框通过同一变换一起移动；轮廓标签保持固定的边线选择顺序，避免可见边长度接近时来回换边。这些调整同时作用于小地图和大地图。
1.5.4 的区域边框使用首尾连接的闭合轮廓，绘制在真实区域范围以内。线宽按实际屏幕像素计算，缩小到细小区域时自动收细；不足四个物理像素的区域用原形状的实心轮廓显示，不会扩大范围或变成十字。该调整同时适用于公会、Residence 和其他区域图层，并保留小数坐标下的平滑移动。
水面现在单独按群系水色和水深分组校准，不再受陆地方块的色相 / 增益限制；浅水基础色还结合客户端可见的水底材质。只用像水面的网页样本建立配色，网页上的草地或缺失数据不会直接用于水面校准。

## 在线玩家、标记与区域图层

1. 按 `O` → 顶部独立的“图层与玩家”，或点击大地图下方的“图层”。
2. 左上角选择“当前: 小地图 / 大地图”。两种地图的显示选择分别保存。
3. 可以独立控制自身位置、在线玩家、玩家名称、图层标签，以及网站实际提供的每个图层；点击“完成”保存并返回。

该界面内分为“显示图层”“图标文字”“生物雷达”，不再进入单独的“图标与雷达”窗口。“图标文字”中，小地图、大地图分别调整各种图标尺寸和文字大小。
所有图标和地图文字的默认大小均为 **6 GUI 像素**；字体大小可以单独设置为 4–18。升级时旧默认图标尺寸会迁移为 6，已经设为其他尺寸的自定义值保留。“图标与字号重置为 6”可以重置当前地图的这组尺寸。
玩家头像与自身头像使用半个 GUI 像素宽的细边框，自身朝向线也采用细线绘制。

在线玩家显示头像，自身带朝向线。优先使用游戏已有皮肤，网页独有玩家使用网站 `faces/16x16/玩家名.png` 头像；加载中或不可用时使用原版默认头像。位置数据来自当前网站公开玩家接口和游戏已接收到的附近玩家；按当前网页世界筛选，同名玩家去重，附近玩家使用游戏中的实时坐标。超过 20 秒未获得有效更新的网页玩家数据不继续显示。

图层名称和开关动态读取自 Dynmap marker sets，不限制插件名称。支持点标记及网站原有 PNG 图标、区域多边形 / 矩形的边框和填色、折线、圆形 / 椭圆区域；遵守网页的默认隐藏状态和可见缩放范围。小地图默认隐藏所有名称，按住 Tab 才显示，松开立即隐藏；可在“图层与玩家”里改成常显。
大地图默认显示短名称。标记 HTML 中的创建时间、创建者和描述会与名称分离，鼠标悬停时才显示详细信息及坐标。
世界边界等不填色的轮廓只在鼠标接近边线时显示提示，边线内外两侧都可触发；边线不在画面内时，不会在区域中央显示“世界边界”标签。领地等有填色区域仍可在内部悬停查看。

默认 Bilicraft 网页本次公开的图层包括 `Markers`、`Stargate`、`Residence`、`公会区域`、`warzone`。空图层也会列出并显示数量 0；它们是否含有图标或区域，由网站当前数据决定。其他网站新增的图层同样会自动出现在列表中。

图层约每 15 秒刷新，图层 JSON 和图标保存在 `cache/satellite-map/markers/` 与 `cache/satellite-map/icons/`。网站离线时保留已缓存的静态标记 / 区域；图层关闭后不会绘制对应图形。每个网站的图层开关分别保存，不会把某网站的设置套到另一个网站。

## 生物雷达与图标尺寸

在“图层与玩家”的“图标文字”页设置尺寸和字号，在同一界面的“生物雷达”页调整分类开关、雷达范围和垂直范围。小地图、大地图分别保存。

默认红点表示敌对，黄点表示中立，白点表示友好。按住 Tab 时生物改为头像，松开恢复分类点。僵尸、骷髅、苦力怕、狼、牛、猪、羊、猫、村民、蝙蝠、马和鹦鹉等使用对应纹理的脸部裁剪。绘制前会检查裁剪区域是否有可见像素；没有标准头像的生物和无法读取的特殊材质显示有填充的二维脸形符号，不再使用容易在小尺寸下显示为空框的三维实体缩略图。
小地图默认启用“高度透明”：生物与自身高度差越大，圆点、头像和边框一起逐渐变淡，最低保留 6% 不透明度。缩小地图后衰减变慢，放大后衰减加快。默认第 2 级、32 格衰减距离时，高度差 32 格约为 50% 不透明度；缩小到第 4 级时约为 80%。
在“小地图 → 生物雷达”可关闭“高度透明”或调整“高度衰减距离”；关闭后该数值恢复为硬性垂直显示范围。大地图保留原有垂直范围设置。
雷达仅使用客户端已收到的附近实体，默认水平范围 96 格，不扫描服务器未发送的生物。高度渐隐开启时不会在 32 格处突然隐藏生物。中立生物会结合客户端可观察到的愤怒 / 目标状态分类，不能保证获取服务器上所有 AI 状态。

## 缩放与瓦片优先级

地图不再只读取当前缩放等级的瓦片：已经加载的各级瓦片会按相同投影坐标对齐，先绘制覆盖大范围的粗瓦片，再覆盖可用的细瓦片。即使缩放等级变化，已有图片仍会参与渲染；细瓦片缺失时保留对应区域的粗瓦片。

1.4.0 将下载记录与 GPU 纹理容量分开统计，并保护正在显示的纹理，避免大量请求挤掉眼前的地图。细节纹理因内存压力释放后，会优先从本地重新读取。
成功加载的瓦片还会在后台合成为多级持久地图，保存在 `cache/satellite-map/overview/`。1.5.0 使用比原先细三级的合成图作为常驻底图，单边采样密度提高 8 倍；缩小时通过面积平均保留图案，减少锯齿和纹理丢失。合成图与原始瓦片按精细程度交错绘制，粗瓦片不会再盖住已经合成的细节。
大地图的自动细节预算从每级 96 张提高到 384 张，覆盖整个可视区域后再逐级细化，仍然先下载大块、同级优先中心。持久地图和细节纹理使用独立缓存，当前可见图像受到保护；缩放、平移和网站断网时继续使用已保存的图像。从未加载、网站未渲染的区域仍需要取得实际图像；网站本身缺少细节时无法凭空补出建筑。

比网站最远缩放额外增加四级，每级再缩小一半；默认网站可从原先最远的 5 级缩小到 9 级，单边覆盖范围扩大 16 倍。额外等级复用网站实际已有的瓦片，不请求不存在的更高等级。

本地磁盘缓存会在后台建立索引，之前保存的细瓦片也能在其他缩放等级下重新加载。下载按粗到细排列，每一级优先获取当前视野中心；拖动或改变缩放后，清掉旧焦点尚未开始的排队任务。8 个并行下载共享连接池，支持的网站使用 HTTP/2 复用连接，并压缩传输 JSON；PNG 避免重复压缩，每个游戏 tick 限制纹理上传数量，减轻加载卡顿。特定 Windows Java 无法初始化 HTTP/2 客户端时自动回退到兼容的 HTTP/1.1。

极大范围视野会限制细节下载数量，逐步加载，避免一次请求数万张图片；已有细瓦片仍优先覆盖粗瓦片。各级都没有图片的未缓存 / 未渲染区域仍会显示占位背景。网站或链路的速度仍会影响首次下载，已有本地缓存可直接使用。

## 本地瓦片缓存

从 1.1.0 起，已获取的地图会保存在当前游戏实例目录：

- `cache/satellite-map/tiles/`：按完整瓦片网址散列保存的磁盘缓存；不同网站、世界和图层互相隔离。
- `cache/satellite-map/sites/`：网站世界列表、投影矩阵及图层配置，保证已知地图在网站离线时仍可读取本地瓦片。

渲染先读本地缓存。本地读取有独立后台线程，不会排队等待慢速 HTTP 下载。达到设置的刷新间隔后，在后台向网站验证 `ETag / Last-Modified`；网站返回新图时，先验证、解码，再原子替换本地文件和游戏纹理。没有这些响应头的网站会正常重新下载并比较图片。
网站返回 `304` 时复用已有图像；断网、HTTP 错误或无效图片不会覆盖原有的可用瓦片。

缓存跨游戏重启保留，只保存实际浏览过的瓦片，不预下载整个网站。首次使用某网站仍需成功联网读取配置。网站离线时，可显示已缓存区域；尚未缓存的区域显示占位背景，隐藏玩家的多世界识别仍需要显式规则或手动选择。
细节纹理通常以 384 张 / 约 64 MiB 为目标，当前可见纹理受到保护，必要时允许短时使用约两倍容量；图标单独缓存最多 64 张。持久合成图通常保留 384 张 128×128 GPU 纹理，可见图受到保护时临时允许两倍容量，合成器也单独限制内存中的节点。
原始地图瓦片磁盘目标上限为 512 MiB，图标为 32 MiB；写入时最多每分钟清理一次较久未使用的数据，允许短时超过上限。合成图另外持久保存，用于保留已浏览区域。本地实时地形只保存在内存中。关闭游戏后可删除整个 `cache/satellite-map/` 释放空间。

## 默认映射

第一组已经配置为：

- 组名：`Bilicraft · Hyperion`
- 服务器：`mc.bilicraft.com:25577`
- 地图：<https://map.bilicraft.com/s2/hyperion/#>
- 网页世界、图层、游戏维度：留空，自动选择。

该网站当前提供 `Paralon`、`artist`、`artvoid`、`HyperionVoid` 等网页世界，平面图层名为 `flat`，部分世界另有 `surface` 斜视图层。
自动模式优先使用网页公开的当前玩家位置确定世界；无法识别时，主世界使用网站第一个可用世界，并在大地图提示。
下界、末地和自定义维度没有匹配世界时会提示配置，不会直接套用主世界地图。
该默认网页本次读取到的四个公开世界中没有明确命名的下界 / 末地图；未公开、未渲染的世界无法从该网址生成地图，需为它们添加实际提供对应地图的网址或网页世界。

## 多服务器 / 群组服

设置中可以新增、编辑、删除任意多组映射。一个组可填写多个入口地址，用逗号分隔；未写端口时使用 Minecraft 默认端口 `25565`。
不同端口视为不同服务器。可填写域名或 IPv4 / IPv6，不会自动把 DNS 别名等同于其解析 IP。

例如同一代理入口的两个子服，可创建两组相同服务器地址、不同地图网址的映射。
如果多个世界位于同一 Dynmap 网站，也可使用相同网址，为各组填写不同的“网页世界名”。

“世界 / 图层”页中的三个可选字段：

| 字段 | 用途 / 示例 |
| --- | --- |
| 网页世界名 | Dynmap 内部世界名，例如 `Paralon`、`HyperionVoid`；留空自动识别 |
| 图层名 | 例如 `flat`、`surface`；留空优先选择 `flat` |
| 游戏维度 | 精确匹配客户端维度，例如 `minecraft:overworld`、`minecraft:the_nether`；留空匹配所有维度 |

网页世界名通常与客户端显示的 `minecraft:overworld` 不同。世界名、图层名区分大小写。
“世界 / 图层”页会读取网站的可用世界列表；将鼠标移至列表上可查看完整提示。

自动识别的行为：

1. 读取当前连接的服务器地址与客户端维度，筛选匹配的组。
2. 约每 6 秒读取候选网站的公开玩家接口，以当前登录用户名匹配玩家。
3. 检查网页坐标与游戏坐标距离不超过 128 格，降低旧数据误匹配的可能。
4. 唯一匹配时自动切换组及网页世界；多个匹配时保留当前匹配组并提示。
5. 按 `B` 或大地图“切换组”按钮进入手动模式；大地图“自动”按钮或显示设置可恢复自动模式。

客户端进入新维度时会立即清除旧的玩家识别结果并重新选择世界。`world_nether`、`Paralon_nether`、`DIM-1` 等名称可自动对应下界，`world_the_end`、`Paralon_the_end`、`DIM1` 等名称可自动对应末地；自定义维度尝试精确匹配网页世界名。
同一主世界维度下的多个世界，通过公开玩家列表中的实际网页世界名切换；一次唯一匹配后，会记住本次连接内该世界与维度的对应关系，并在玩家接口暂时失效时保留上次确认的世界。
不同维度已有明确映射组时，具体维度规则优先于通用规则。网站世界名不规则、下界 / 末地各有多个候选，或玩家被隐藏时，可为同一入口新增不同的“网页世界名 + 游戏维度”映射组。

**代理内部切服时，客户端不一定能收到后端 IP。纯客户端 MOD 无法保证识别任意隐藏后端。**
如果网站隐藏玩家、玩家不在公开列表内、数据更新滞后或两服同时公开同名同坐标玩家，自动识别可能无法确定；此时使用手动切换，并为组明确填写网页世界名。
本 MOD 不向服务器发送获取后端信息的插件消息，也不要求服务器插件。

## 网站兼容性与网络

- 支持公开 Dynmap HDMapType 地图，PNG / JPG 瓦片；同时支持 flat 与具有有效投影矩阵的斜视地图。
- 会读取 `standalone/config.js` 内的配置、更新、瓦片路径；也尝试静态 `standalone/dynmap_config.json` 与动态 `up/configuration` 接口。
- 支持地图部署在网址子目录下，例如默认的 `/s2/hyperion/`。
- 使用游戏玩家坐标绘制本人的位置，地图图像来自网站已渲染的区域。
- 网页未渲染区域、HTTP 错误和断网显示占位背景，可自动重试；瓦片更新时保留旧图直到新图可用。
- 网络、磁盘读写和图片解码在后台线程执行，GPU 纹理更新在客户端线程执行。每次最多排队 32 个下载任务和 64 个独立的本地读取任务。
- 网站探测只针对当前地址 / 维度匹配的组；在设置界面浏览组时也会读取该组的世界列表。
- 不包含完整网页浏览器，不执行网页 JavaScript。BlueMap、squaremap、需登录 / Cookie / 验证码的网站及非公开接口暂不支持。
- 不上传游戏坐标，不发送网页聊天消息；HTTP 请求会向配置的网站暴露正常网络访问所需的 IP 和请求路径。

## 配置文件

配置保存于游戏实例的 `config/satellite-map.json`。可直接在游戏中修改。
写入采用临时文件替换；无效 JSON 会先备份为 `.invalid-时间戳` 再恢复默认配置。
修改文件后重新启动游戏生效。

## 从源码构建

需要 JDK 21，首次构建会下载 Gradle、Minecraft 和 Fabric 依赖。

```powershell
.\gradlew.bat build
```

macOS / Linux：

```sh
sh ./gradlew build
```

生成的可安装 JAR 位于 `build/libs/satellite-map-1.5.4.jar`。`-sources.jar` 是源码包，不能作为 MOD 安装。

```powershell
.\gradlew.bat test       # 投影、维度 / 多世界、缓存更新 / 断网 / 损坏、拖动布局等离线测试
.\gradlew.bat liveTest   # 真实读取 Bilicraft 配置、玩家、9 张瓦片、marker sets 和网站图标
.\gradlew.bat runClient  # 开发客户端；使用工程独立 run 目录
.\gradlew.bat runClientGameTest -Pclient_smoke # 独立客户端：界面、原版重绑、维度切换、断网站缓存渲染
```

客户端测试若遇 Fabric 测试框架的 `Network synchronizer in invalid state`，可按其日志提示关闭测试专用的严格包同步器，再运行同一测试；实际世界切换、纹理和截图断言仍会执行：

```powershell
$env:JAVA_TOOL_OPTIONS="$env:JAVA_TOOL_OPTIONS -Dfabric.client.gametest.disableNetworkSynchronizer=true"
.\gradlew.bat runClientGameTest -Pclient_smoke
```

`liveTest` 会生成 `build/reports/live-map-preview.png`，该图片是从真实网站瓦片拼接的验证图。
客户端测试截图位于 `build/run/clientGameTest/screenshots/`；测试创建独立的临时平坦世界，使用匿名开发玩家，不连接真实多人服务器。
工程为 Windows 中文路径适配了 Java 21 启动参数文件编码，同时明确以 UTF-8 编译源码、处理资源、保存配置和读取 HTTP 文本。
联网测试不会登录 Minecraft 服务器。真实账户登录及实际群组内切服仍应在用户自己的游戏环境验证。

本地网络无法顺畅访问 Fabric Maven 主域名时，可以使用官方备用域名：

```powershell
.\gradlew.bat build -Pfabric_maven_url=https://maven2.fabricmc.net/
```

若特定 Windows / JBR 环境遇到 `Unable to establish loopback connection`，为该构建进程指定较短临时目录：

```powershell
New-Item -ItemType Directory -Force C:\Temp | Out-Null
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=C:\Temp -Djava.io.tmpdir=C:\Temp'
.\gradlew.bat build
```

## GitHub 自动构建与发布

推送任何 tag 都会运行 [Tag build and release](.github/workflows/release.yml)：使用 Java 21 和工程固定的 Gradle Wrapper，执行 `clean build`（包含离线测试），构建成功后上传 Actions 产物，并自动创建对应的 GitHub Release。版本号从 tag 取得，例如 `v1.5.5` 会构建版本 `1.5.5`，不必为了构建覆盖本地的 `gradle.properties`。建议使用 `v主版本.次版本.修订号` 格式。

```sh
git add .
git commit -m "Prepare release 1.5.5"
git push origin main
git tag -a v1.5.5 -m "Release 1.5.5"
git push origin v1.5.5
```

Release 包含可安装的 MOD JAR、源码 JAR、MOD 安装 ZIP 和 `SHA256SUMS.txt`；完整工程源码也可通过 GitHub 自动生成的 Source code 下载。`-sources.jar` 不能作为 MOD 安装。Actions 产物保留 30 天，Release 附件长期保留，测试报告单独上传。
也可以在 Actions 页面手动运行工作流；选择分支时使用 `gradle.properties` 中的版本号，仅上传构建产物，不创建 Release。
工作流使用仓库自带的 `GITHUB_TOKEN`，无需额外配置发布密钥。联网测试和需要图形环境的客户端测试仍按上面的命令手动运行，不作为 tag 构建的前提。
